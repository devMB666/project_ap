# Практическая работа №13 — Модуль системы централизованного теплоснабжения

Учебный прототип на Go 1.23+ и chi v5. Пользователь регистрирует источник, отправляет измерение и при необходимости читает уведомление о тревоге. Каждый сервис — отдельная программа с собственным хранилищем в памяти. Между сервисами передаются только HTTP-запросы и JSON.

| Сервис | Адрес с хоста | Ресурс |
|---|---|---|
| source-service | http://127.0.0.1:5000 | /sources |
| telemetry-service | http://127.0.0.1:5001 | /measurements |
| notification-service | http://127.0.0.1:5002 | /notifications |

На каждом порту GET /healthz проверяет, отвечает ли соответствующий процесс. Внутри Compose телеметрия обращается к http://source-service:5000 и http://notification-service:5002 по DNS-именам. Данные между процессами не делятся.

## Запуск

В корне распакованного проекта, при установленном Docker с Compose:

```sh
docker compose up --build -d
docker compose ps
docker compose logs -f
```

Выход из просмотра журналов — Ctrl+C. Остановка стенда: `docker compose down`. Данные каждого сервиса исчезают при остановке его процесса, в том числе при перезапуске контейнера.

## REST API

Для каждой коллекции есть POST для создания и GET для списка. По адресу коллекция/{id} доступны GET, PATCH и DELETE. Поля PATCH: у источника — name и/или enabled, у измерения — review_note, у уведомления — read. Исходные данные измерения и текст уведомления неизменяемы. DELETE возвращает 204, отсутствующая запись — 404. Удаление ресурса не удаляет записи из другого сервиса. DELETE измерения скрывает запись и оставляет ключ занятым до перезапуска, чтобы повтор удалённого пакета не восстановил его; такой POST возвращает 410.

| POST /measurements | Ответ |
|---|---|
| Новый допустимый пакет | 201, в теле измерение. Статус уведомления: not_required, sent или pending |
| Тот же ключ (source_id, stream_id, seq) и те же значения | 200, существующее измерение. Если статус pending, делается попытка доставки |
| Тот же ключ с другими данными | 409 measurement_conflict |
| Источник неизвестен или отключён | 422 source_not_found / source_disabled |
| Реестр недоступен | 503 source_unavailable, Retry-After: 1; новый пакет не записывается |

POST /measurements/{id}/notification повторяет попытку для сохранённой тревоги: 200 и sent при успехе, 503 при недоступности сервиса уведомлений, 409 если уведомление не требовалось. Уведомление для тревоги использует ID измерения. POST /notifications принимает поля id, measurement_id, text, создаёт запись с кодом 201 и пишет сообщение в журнал; точный повтор — 200, конфликт — 409.

## Postman и проверка

Импортируйте `postman_collection.json`. В запущенном стенде выберите **Run collection** и запускайте с первой папки. Первый запрос задаёт уникальные переменные, ID ответов сохраняются автоматически. 34 запроса покрывают доступность, CRUD, взаимодействие, повтор и конфликты.

Для тестирования сценариев с отключением сервисов предусмотрен скрипт: `demo_degradation.sh`

В прототипе нет аутентификации, TLS, фоновой очереди доставки или постоянной БД. sent означает, что другой сервис принял и зарегистрировал уведомление; внешняя рассылка не выполняется. Тайм-аут каждого HTTP-вызова 750 мс. Чтение реестра повторяется один раз после 100 мс при сбое сети или 5xx. Повтор доставки запускается явно или повторной отправкой пакета.
